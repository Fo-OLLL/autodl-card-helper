# AutoDL 抢卡助手 v0.3.4

可直接安装的 Tampermonkey 油猴脚本，用于 AutoDL **普通容器实例**。使用当前网页登录状态，不需要填写开发者 Token。

## 安装和使用

1. 在 Chrome / Edge 安装 Tampermonkey，确保扩展允许用户脚本运行。
2. 打开 [安装 / 更新脚本](https://raw.githubusercontent.com/Fo-OLLL/autodl-card-helper/main/autodl-helper.user.js)，在 Tampermonkey 中安装或更新。
3. 登录 `https://www.autodl.com`，打开控制台或算力市场，点击右下角 **AutoDL 抢卡**。
4. 在“设置”调整全局检查间隔，默认 10 秒、最低 5 秒；点击“测试提醒”解锁声音、检查桌面通知。
5. 选择“抢开机”或“抢新实例”，配置后点击启动。点击启动即授权脚本自动执行所选实例关机、GPU 开机或新实例创建，并产生网站正常计费。

保持浏览器和至少一个 AutoDL 标签页打开。刷新、导航到同站其他页面或重新打开后，未完成任务会自动恢复。浏览器关闭、电脑休眠、网页被丢弃期间无法执行；后台标签页的实际间隔可能被浏览器延长。

## 自动更新

脚本已配置 `@updateURL` 和 `@downloadURL`，由 Tampermonkey 检查 GitHub `main` 分支上的新版本并更新。旧版本用户先手动更新一次，再在油猴“设置 → 脚本更新”设置检查间隔，并确认本脚本允许检查更新。需要立即更新时，可执行“检查更新”或打开上方安装 / 更新链接。

更新后刷新 AutoDL 页面生效。请更新同一个脚本，不要删除旧脚本，以保留任务、配置和 SendKey。每次发布提高 `@version`；只修改代码而不提高版本号不会触发正常版本更新。浏览器必须运行且能访问 GitHub Raw 地址；更新确认由油猴设置和新增权限决定。

## 两种模式

### 已有实例抢开机

打开“抢开机”后实例列表自动加载，多选目标实例，然后启动。每个实例都有独立任务；全部选中的目标都成功后，这组需求才算满足。

实例列表显示具体显卡型号与卡数，运行状态 `running` 为绿色，关机状态 `shutdown`（包括开机/运行错误后关机）为红色。无卡模式显示为中文辅助标记，同时保留实例的显卡型号。

- 已关机：持续尝试 GPU 开机。
- 正在无卡模式运行：先保持运行并查询原主机库存；仅当空闲 GPU 数量达到实例所需卡数时才关机，确认关机完成后尝试 GPU 开机。库存不足、状态未知或查询失败时不会关机。
- 正在创建、启动、关闭：保留任务，等待状态转换。
- 已进入 GPU 运行状态：该实例任务成功并发送通知。

检测到卡后，无卡转 GPU 的关机操作会停止实例中当前正在执行的进程。库存检测并非预留，关机过程中卡仍可能被其他用户抢走，此时继续重试 GPU 开机。脚本只操作你选中的实例，不会释放实例。

#### 克隆为新实例并开机（含数据盘）

在“抢开机 → 开机方式”选择“优先原实例开机，必要时克隆（含数据盘）”，再启动所选任务。

默认同时监控原实例和克隆机会，原实例优先级更高，两条路径共用一个任务：

- 原实例已处于 GPU 运行状态时，直接完成任务，不再克隆。
- 原主机空闲卡数足够时，按原实例当前卡数优先原地开机；无卡模式先关机再开机。克隆筛选条件只用于备用克隆目标，不改变原实例配置。
- 原主机库存不足，或原地开机被平台明确拒绝时，才查找符合筛选条件的克隆目标。克隆提交前再次核对原主机库存。
- 原实例开机请求已受理或超时结果不确定时，保持等待，不并行创建克隆。观察到启动后再次关机时允许转入备用克隆；未能确认结果时保留任务。
- 任一路径成功后该任务停止并通知；一旦已提交克隆或等待核对克隆结果，就只跟进该目标，不再另开原实例，避免重复运行和计费。

- 自动加载源实例所在地区的卡型，支持多选 GPU 并设优先级、目标卡数、最低内存、驱动筛选、主机可扩容容量及实际扩容；与抢新实例一致，驱动版本自动加载供选择。
- 不提供地区或镜像选择：每个克隆任务固定在源实例地区，系统盘使用源实例环境。多选不同地区的源实例时，只列出这些地区共同支持的卡型，各任务仍各自在源地区克隆。
- 先保持源实例运行并监控目标库存，发现同地区其他主机满足所选全部条件后，才关机源实例；关机后重新确认库存并按量创建一个新实例。更换卡型仍需要兼容源系统盘的芯片厂商、CPU 架构及 CUDA 环境；不兼容主机会跳过。
- 使用平台克隆接口复制系统盘，固定开启 `copy_data_disk_after_clone`，将数据盘一起复制。
- 根据源数据盘的基础容量和额外扩容计算目标扩容，确保目标盘不小于源盘；容量信息缺失时保留任务等待核对。
- 旧版已保存的克隆任务继续沿用原型号与卡数；若需改用其他卡型，请取消旧任务后使用新筛选创建任务。
- 若最终使用克隆，源实例保留并保持关机，脚本不释放、不覆盖源实例，新实例产生自己的计费；若原地开机成功，则直接使用原实例，不创建新实例。
- 新实例实际进入 GPU 运行状态且平台报告数据盘复制成功后，该任务才完成并通知。复制中、失败或状态缺失时均不冒报成功。
- 克隆请求超时后沿用唯一名称核对，不重复创建。平台报告系统克隆失败时重试原目标；数据盘复制失败会保留待完成任务，需在控制台核对处理。

克隆会终止源实例当前进程，请先保存工作。初次发布以模拟接口验证流程，尚未在真实账户上执行克隆；如果平台的复制状态字段变化，任务会继续保留并显示状态，而不会将 GPU 已运行误判为数据盘也已完成。

参考：[AutoDL 官方同地区迁移/克隆说明](https://www.autodl.com/docs/migrate_instance_2/)。

### 算力市场抢新实例

每个任务创建 **一个实例**，可同时添加多个任务，各自独立完成。支持：

| 条件 | 规则 |
| --- | --- |
| GPU 型号 | 多选，使用 ↑↓ 设置顺序；优先级高于地区 |
| GPU 数量 | 每个实例需要的卡数，必须在同一台主机上满足 |
| 最低内存容量 | 实例总内存 ≥ 设置值，单位 GB；按 `mem_per_gpu × GPU 卡数` 计算，0 不限制。启用后，内存信息缺失的主机会跳过 |
| 地区 | 多选，使用 ↑↓ 设置顺序；匹配任一选中地区 |
| 显卡驱动 | 读取所选地区及卡型主机的已有版本；最低版本使用下拉选择，指定版本支持勾选多个，也可不限制 |
| 主机可扩容容量 | 至少达到设置的 GB 数值；独立于实际扩容大小 |
| 实际额外扩容 | 相对主机基础数据盘增加的 GB；0 表示不额外扩容 |
| 镜像 | 实时读取官方基础镜像或自己的私有镜像 |
| 计费 | 固定按量计费 |

面板按浅色圆角分区排列，依次配置：

1. **选择地区**：地区自动加载，多选目标机房。
2. **选择 GPU**：选择地区后自动加载相关型号，再选择卡型和优先级。显示这些地区存在的型号，包括暂时没有空闲卡的型号，便于持续等待。
3. **设置筛选条件**：选择 GPU 后自动加载已有驱动版本，通过下拉框选择最低版本或勾选指定版本；多选项采用等宽网格卡片。驱动读取包含当前无空闲卡的主机，同时可设置 GPU 数量与磁盘容量。
4. **选择镜像**：选择 GPU 或更改镜像来源后，自动加载官方基础镜像或自己的私有镜像。
5. **创建监控任务**：命名并启动任务。

更改地区会清空旧的 GPU、驱动和镜像选择并自动加载相关型号；更改 GPU 后，驱动与镜像自动重新加载，避免使用不匹配的配置。连续选择使用短暂防抖，过期响应不会覆盖新选择，无需点击任何“读取”按钮。配置过程中到达顺序与抢卡优先级分开：抢卡仍以 GPU 型号优先，地区次之。

同一任务所选 GPU 要采用相同芯片厂商和 CPU 架构。没有单独的 CUDA 版本筛选项；若镜像声明的 CUDA 版本超过主机支持上限，脚本会跳过该主机，避免创建后无法开机。

符合条件的主机按 GPU 顺序、地区顺序排序，同等级按主机 ID 排序。卡被别人抢走后，任务继续重试。多个任务同时监控，写请求依次发送，避免本脚本的任务互相竞争；大规模任务组的一轮耗时可能超过设置间隔。

新实例使用 `ADLH-<任务UUID>` 作为名称，供刷新后的创建结果核对。待任务完成后可以在 AutoDL 控制台重命名；创建结果尚未确定期间请保留名称。

## 持久化和异常处理

- 只有你主动取消或实例实际进入 GPU 运行状态，任务才终止。请求受理不等于成功。
- 配置、执行阶段、实例 UUID 和通知记录存入 Tampermonkey 本地存储，不保存 AutoDL 登录 Token。
- 断网、登录过期、余额不足、接口错误：保留任务，按退避间隔重试，最长 5 分钟；登录后或问题消除后继续。
- 任务绑定创建时的账号；切换账号后不对新账号执行原账号任务，切回后继续。
- 多标签页通过 Web Locks 保证同一时刻只有一个执行者，共享全局检查间隔和任务记录；需要新版 Chrome / Edge。
- 创建前保存唯一名称和请求意图。超时、服务器错误或响应无法解析时，继续检查实例列表，**不自动重复下单**。
- 如果长时间无法确定创建结果，任务仍保留。至少等待两分钟并在控制台核对未创建后，可点“已核对未创建，重新尝试”。网站普通实例接口没有已确认的幂等保证，所以不能仅凭超时认定失败。
- 取消只阻止后续请求，无法撤回已经发送的关机、开机、创建请求。已返回的实例 UUID 会保存供核对。

## 每个实例的通知

默认启用面板状态、提示音和桌面通知。浏览器或系统可能要求打开 Tampermonkey / 浏览器通知权限。刷新后的声音受自动播放限制，需要再次点击“测试提醒”解锁。

Server酱为可选功能：

1. 前往 [Server酱 Turbo](https://sct.ftqq.com/) 或 [Server酱³](https://sc3.ft07.com/)，获取 SendKey 并绑定微信推送渠道。
2. 在“设置”勾选 Server酱，填写 SendKey，保存。
3. 点击“测试提醒”验证。

支持 `SCT…` 和 `sctp…` 格式。SendKey 仅保存于油猴本地存储，不进入源码、日志或 AutoDL 请求；通知通过油猴跨域请求直接发往 Server酱。若你启用了油猴云同步，存储是否同步取决于扩展设置。

微信通知失败会单独退避重试，不改变抢卡成功状态。网络超时后的重试可能造成重复推送。使用的是 Server酱提供的微信通知渠道，实际接收方式和额度由你的 Server酱账号决定。

## 验证和当前边界

运行 `npm test` 验证业务逻辑；运行 `npm run check` 检查脚本语法。不需要构建，不需要运行服务器。

本版已核对 2026-10-13 AutoDL 公开网页前端代码的请求路径、请求结构、驱动/磁盘字段、基础镜像树，以及实时公开 GPU / 地区列表。普通实例的登录后接口没有稳定公开 API 合同，网站更新可能需要适配。

交付前使用模拟接口验证状态机、恢复、取消、分页、请求不确定性和页面交互。**尚未在真实登录账号上验证实例创建、无卡关机和 GPU 开机，也未使用真实 SendKey 发通知。** 首轮安装后应先读取列表和测试通知，再用一个实际需要的任务观察日志。当前不支持 Pro 实例、社区镜像、包日/周/月和关闭浏览器后的后台执行。
